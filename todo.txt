identity-service TODOs (security + enterprise hardening)
=======================================================

This file tracks follow-up work for identity-service.
Current status: MVP is functional (auth + refresh rotation + orgs + memberships + invites + RBAC + audit + health + signup).
Role verification: test-roles.ps1 (Windows) and test-roles.sh (macOS/Linux) are in place for contributors to verify roles and permissions via API (no DB access).

OPEN ITEMS
----------

1) Password reset placeholder: add audit event on request
   - Current behavior: `POST /auth/password-reset/request` returns 202 always (correct), but does not emit an audit log.
   - Add: `identity.auth.password_reset.requested` audit event with non-sensitive metadata (e.g. org_slug if provided; never store raw email).

2) Email verification (future)
   - Send verification email with one-time token (short TTL; hashed at rest).
   - Endpoint: `POST /auth/email/verify { token }`.
   - Audit events:
     - `identity.email.verify.requested`
     - `identity.email.verified`

3) Password reset flow (with email delivery)
   - One-time, short-lived tokens; hashed at rest.
   - On completion: revoke-all refresh tokens for that user/org + audit `identity.auth.password_reset.completed`.

4) MFA (Multi-Factor Authentication)
   - Phase 1: TOTP enrollment + challenge for high-privilege roles.
   - Phase 2: WebAuthn (passkeys/security keys).
   - Recovery codes required.

5) SSO (SAML / OIDC)
   - OIDC first, then SAML.
   - Strict org isolation; map identities by verified email + org rules.

6) Signing key rotation (future)
   - Support multiple active signing keys (`kid`) to rotate without instant logout.
